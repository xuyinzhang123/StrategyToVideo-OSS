## 2. 逐份说明与预期视频

### 1) `timeseries_single.csv` — 最小字段单序列

```csv
date,value
2024-01-31,100.0
```

- 只有两列，正好是 A 类的**最小字段**；无 `series` 列，整个文件视为一条序列。
- 24 个观测点，2024-01-31 → 2025-12-31，月度。
- 首值 100.0，末值 141.3，最小值 100.0（2024-01），最大值 141.3（2025-12）。
- 无空值、无重复、严格升序。

**预期视频**：单条折线 24 段生长，约 20 s；首/末/极值四处定点标注；Y 轴自适应并标注范围；页脚「用户导入 · timeseries_single.csv · 单位：未声明」；中性色板，不用红绿；无配音无字幕。

---

### 2) `timeseries_multi.csv` — 三序列同日期集合

```csv
date,series,value
2025-01-31,产能利用率,71.2
2025-01-31,良品率,64.5
2025-01-31,设备稼动率,58.1
```

- 3 条序列 × 各 12 个月 = 36 行，三序列日期集合完全一致 → **不触发** `W_RAGGED_SERIES`。
- 序列名：产能利用率 / 良品率 / 设备稼动率。

**预期视频**：3 条折线同图生长，约 25 s；顶部图例「序列名 + 末值」；三条线颜色可区分且不使用红涨绿跌；缺口不适用。

### 3) `cross_section.csv` — 8 项横向对比（含负值）

```csv
label,value,group,value2
渠道A,132.5,线上,118.0
...
渠道H,-12.4,其他,-8.7
```

- 8 行，2~60 行区间内；`label` 唯一。
- 数值范围 −12.4 ~ 132.5，合计 532.1；含 1 个负值（用于验证负向条形）。
- `value2` 整列有值（上期对照）。

**预期视频**：横向条形按 `value` 降序逐条生长，约 18 s；每条标数值 + 占比（口径「该行 ÷ 合计」，画面写明）；`渠道H` 的条形从零轴向左；`value2` 作并列第二根；页脚「用户导入 · 按 value 降序 · 时点：未声明」。

### 6) `warn_stock_calendar_gap.csv` — 缺口只警告，不拒绝

- 在上述 260 行中删除 `2024-04-01` ~ `2024-04-16` 的 12 个工作日，剩 248 行。
- 相邻两行之间缺失 **12 个工作日** → 超过 10 天阈值 → `W_CALENDAR_GAP_LARGE`。
- 按契约，**不拒绝**：无法从数据本身区分「长假」与「漏行」。

**预期视频**：正常出片，但页脚必须写「区间含 1 处缺失工作日（12 天），按连续交易日处理」，且校验报告提示核对是否漏行。MACD 按 bar 序号推进，漏行会让等效回看窗口变长——这一点由画面声明。

---

### 7) `warn_stock_descending.csv` — 整体降序自动反转

- 与样例 4 同一批数据，行序完全逆序（最新在前）。
- 契约 §1.4：只对「整体降序」放行 → 自动反转 + `W_DESC_ORDER`。
- 未配套分红文件 → 另触发 `W_NO_DIVIDENDS`，画面须标「未计现金分红」。

**预期视频**：与样例 4 等效（反转后数据一致），但页脚多一行「原始文件为降序，已反转」。

### 8) `warn_timeseries_ragged.csv` — 序列参差

- 3 条序列，点数 **A 10 / B 12 / C 11**（A 缺 2025-04、2025-05；C 缺 2025-08）。
- → `W_RAGGED_SERIES`；渲染时缺处断线，**不插值、不前向填充**。

> 这张表原先写成「B 缺 2 个月」，与实际文件不符；`npm run check:samples` 实跑后已按文件更正（A 才是缺点的那条）。

**预期视频**：三条折线各有断点，画面标注「各序列区间不一致」。

---

### 9) `invalid_stock_missing_column.csv` — 缺必填列

表头 `date,open,high,low,volume`，缺 `close` → `E_MISSING_COLUMN`（定位到表头行）。
报错必须列出该类要求的完整列清单，让用户知道还缺什么。

---

### 10) `invalid_stock_duplicate_date.csv` — 重复日期

第 12 行 `2024-01-15` 与第 11 行同日 → `E_DUP_DATE`，报错给出两个行号。
不自动去重：同日两条记录可能是数据源拼接错误，静默保留其中一条会改变收益率。

---

### 11) `invalid_stock_bad_number.csv` — 引号内千分位

第 7 行 `close` 写成 `"1,234.50"`（带千分位，已加引号以免被当成分列）→ `E_THOUSANDS_SEPARATOR`。
报错格式：`行号 + 列名 + 原始文本 + 「删除逗号后重传」`。这是**独立错误码**，不再归入 `E_BAD_NUMBER`——因为这个数字本身是合法的，只是写法不被接受（理由见契约 §1.2：逗号在德语区是小数点，任何自动清洗都会对一半用户是错的）。

> 这份样例同时说明了为什么必须先有引号规则：不加引号时 `1,234.50` 会被逗号切成两列，错误会先表现为 `E_ROW_FIELD_COUNT`，反而掩盖了真正的问题。

---

### 12) `invalid_timeseries_unordered.csv` — 部分乱序

第 4 行 `2024-08-31` 后面接 `2024-04-30`，既非升序也非整体降序 → `E_DATE_UNORDERED`。
只有「整体降序」才允许自动反转；部分乱序意味着数据可能被拼接过。

---

### 13) `invalid_cross_section_duplicate_label.csv` — label 重复

`渠道C` 出现两次 → `E_DUP_LABEL`。
不自动合并：同一名称的两行可能是两个口径、也可能是复制粘贴错误，合并会编造出新数字。

## 4. 未覆盖、需后续补样例的情形

| 情形 | 为什么本轮没做 |
|---|---|
| `adjust=qfq` + 提供分红 → `E_DIV_CONFLICT` | 冲突由「文件 + 表单参数」组合触发，不是文件本身的性质，无法用单独一份 CSV 表达 |
| 起点 < 2015-08-01 → `E_DATE_BEFORE_COST_RULES` | 需另造一份 2014 年前的行情，且与现有费率表冲突；等 V-01/V-02 结论出来再定是否放开 |
| 配股/缩股方案 → `E_UNSUPPORTED_ACTION` | 需要在分红 CSV 的 `plan` 里写具体方案文本，属组合用例 |
| 非主板代码 / ST 简称 → `E_UNSUPPORTED_BOARD` | 由表单元数据触发，与文件内容无关 |
| >60 行横向对比、>6 条序列 | 上限类用例，可程序化生成，不必占用样例目录 |
| GBK 编码文件 | 需写二进制样例；建议实现时用临时文件测试，不入库 |
